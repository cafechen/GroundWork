## Verdict / 结论

**Partially aligned; a useful engineering foundation, not a fully enforced or
closed-loop AI-native SDLC.** Code has real tests, strict contracts and preserved
evidence. Documentation records intent and boundaries. But approval stages are not
separate commits, review is not independent, most governance is advisory, and the
reported first-use defects have not become a verified repair loop.

**部分符合，有工程基础，但尚未形成强制执行、缺陷闭环完整的 AI-native SDLC。**
代码有真实测试、契约与证据，文档有需求和边界；但缺少分阶段审批提交，审查不独立，
多数治理仍是约定，首次使用缺陷也尚未完成“复现—回归—修复—验收”闭环。

## Findings / 发现

### Important: incomplete route can look saved / 重要：未完成路线可能看起来已保存

Evidence: `src/platform.js` functions `pick`, `savePark`, `objectDialog`, and the
`finish-route` handler. Picked points live in `routeDraft`; `savePark` submits
`draft` and shows a saved toast. Only finishing and saving the object dialog moves
points into `draft.objects`. Reported screenshots show this exact mismatch.

证据：上述函数中，点选路线存于 `routeDraft`；`savePark` 只提交 `draft` 并提示已保存。
只有“完成路线”且保存对象弹窗，才写入 `draft.objects`。用户截图呈现这一状态错位。

Impact: a user can reasonably believe a visible route is ready but cannot create
a task. `scripts/platform-smoke.mjs` explicitly finishes the route before saving;
it does not exercise Save scene with an unfinished route. This is code inspection
plus reported evidence, not a newly executed browser reproduction this audit.

影响：用户认为可见路线已保存，却无法创建任务。现有浏览器测试主动先完成路线，
没有测未完成时直接保存。本轮证据为代码核对加用户报告，并非重新执行浏览器复现。

Proposed next acceptance, **not implemented**: explicit draft state; either block
save with recovery guidance or include route completion; add a failing browser
regression first, and verify reload retains exactly the promised route.
建议验收（**未实现**）：明确草稿状态，保存时阻止并引导或完成路线；先补失败回归，
再验证重新载入确实保留界面承诺保存的路线。

### Important: startup validity is not explained / 重要：缺少可操作的启动检查

Evidence: `taskDialog` gives a combined missing-device/route toast;
`parkRunSchema` rejects spawn farther than 2 m; `simulatePark` stops on initial
sampled contact. Front-end instance entry remains numeric. The user encountered
all three barriers. `tests/platform.test.js` covers rejection/contact mechanics,
but those tests do not validate a beginner's ability to resolve the error.

证据：任务弹窗用一个提示合并设备/路线条件；运行契约拒绝距离起点超过 2 米；
仿真遇初始接触即停止；实例位置仍需数字输入。用户连续遇到这些障碍。单测覆盖了
拒绝和接触计算，但没有证明首次使用者知道如何解决。

Proposed next acceptance, **not implemented**: pre-run checklist with same-map/floor,
completed route, spawn distance and full-body initial clearance; show distances,
obstacle/body IDs and corrective actions. Keep the numerical criteria, do not
remove collision checks to get motion. Preflight must not be called route planning.

建议验收（**未实现**）：运行前显示地图楼层、完成路线、起点距离及完整车体初始
净空检查，并给距离、障碍物/车体 ID 和处理入口；不能删碰撞检查换取车动，也不能
把预检称为自动路径规划。

### Important: audit trail lacks stage boundaries / 重要：审计链缺少阶段边界

`git log` has two commits at this baseline: `1683576`, then `a634805`. The latter
adds plans, tests, implementation and reviews together. Historical records describe
accepted user directions and failed-then-passing checks, but Git cannot independently
establish a plan-approval commit or a failing-test commit before the implementation.
The remote release was packaged from a dirty worktree before `a634805`, with hashes;
do not relabel it a release built from that later commit.

基线仅两个提交，后一提交把计划、测试、实现、自检一起加入。历史记录描述需求确认
及先失败后通过，但 Git 无法独立证明事前计划审批或修复前失败测试的提交。远端包
来自 `a634805` 之前的工作区，有哈希但不能改称由这个后来的提交构建。

Next: on separately authorized changes, record explicit stage/approval identity and
scope, use small reviewable commits and tie release manifests to exact revision,
dirty state and executed evidence. Never backdate artifacts to repair this gap.
后续获准变更应记录阶段、审批人和范围，小步提交，并将发布清单绑定准确版本、
脏状态和验证证据；不得倒填历史掩盖缺口。

### Important before public release: authority/security / 公开发布前的重要边界

Trusted-LAN/no-auth is explicitly accepted, not an accidental missing login.
`server/http.mjs` host/origin/body/static-file guards and `platform-store.mjs`
reference guards are real application controls, but neither authenticate an
operator. Real control remains unavailable. Redistribution authority for copied
code is still a [provenance limitation](../source-provenance.md).

可信局域网免登录是明确接受的预览边界，不是意外漏登录。HTTP 主机/来源/体积/静态
路径和资源引用检查是真实控制，但不认证操作人。实机控制未接通；平移代码公开再分发
授权仍需核实。不能把本轮通过测试当作公网或商业发布批准。

### Process gaps / 流程缺口

- No verified hosted CI/branch protection, independent reviewer, enforced test-edit
  protection, secret-scanning gate, agent-config eval harness or release approval hook.
  / 未验证远端 CI/分支保护，无独立审查、测试编辑保护、密钥扫描门禁、代理评估或发布审批钩子。
- CI omits browser QA, ready-yard preflight and documentation checks. Local success
  is useful but not a continuous enforced gate. / CI 未覆盖浏览器、示例预检和文档检查。
- Initial documentation had English-only body sections, stale file-tree/storage
  claims and historical approvals near active guidance. This documentation change
  addresses wording/navigation, not application defects. / 原文档双语不全、部分结构和
  存储说明过期、历史与现状易混淆；本轮修正文档，不冒充修复应用。
- Agent rules have candidate examples in policy, not executed agent evaluations.
  A passing app suite is not a passing evaluation of an agent's permission behavior.
  / 政策只有代理评估候选案例，未运行；应用测试不等于代理权限行为评估。

## Priority / 优先顺序

1. Close the reported first-use defects with failing regression → fix → visual
   acceptance; retain the ready example as a baseline, not a workaround forever.
   / 先闭环首次使用缺陷，样例作为基线而不是长期替代修复。
2. With separate implementation approval, add lightweight CI checks for the demo,
   bilingual documentation and essential browser flow; verify hosted execution.
   / 另行获准后加示例、双语文档、关键浏览器流程的轻量 CI，并核实远端执行。
3. Establish reviewable stage/release evidence before public release; add stronger
   governance/evals only when scope and cost are agreed. / 公开发布前建立阶段和发布证据；
   更强治理与评估按需求及预算授权，不一次堆满工具。
